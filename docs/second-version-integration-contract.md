# عقد دمج النسخة الثانية في XDAW NOVA

## مصدر الحقيقة

يظل مشروع **`/home/ubuntu/daousha`** هو المنتج الأساسي المنشور. تستخدم النسخة الثانية (`daousha-platform`) مرجعًا للمزايا والواجهة وأي تكاملات موثقة، ولا تستبدل المنتج الأساسي تلقائيًا ولا تنقل بياناته أو جداول تشغيله بلا مراجعة.

| المجال | ما يمكن مراجعته ودمجه | ما لا ينتقل تلقائيًا |
|---|---|---|
| الواجهة | تبويبات غرفة العمليات، حالات التحميل/الخطأ/الفراغ، عرض صحة المنصات | بيانات مثال أو أرقام أو نشاط غير مستند إلى خادم الإنتاج |
| التشغيل | مراقبة الصحة، عرض آخر فحص، منطق الإيقاف الآمن | تشغيل دوري جديد قبل توافقه مع Heartbeat وحواجز المشروع الأساسي |
| النشر | موصلات مثبتة باختبارات وسجلات فشل واضحة | أي نشر عام أو صف انتظار لا يمر بالحقوق والسلامة والمعاينة والتأكيد |
| المنصات | إعدادات OAuth وعقود التحقق الرسمية | ادعاء أن Facebook أو TikTok مفوضان من دون فحص رسمي ناجح |
| الأسرار | أسماء المتغيرات ووظيفتها فقط أثناء المراجعة | قيم الرموز ومفاتيح التطبيقات أو كلمات المرور في الكود أو الدردشة أو GitHub |

## تسليم النسخة الثانية

لا يبدأ الدمج التنفيذي قبل توافر هذه العناصر من النسخة الثانية: نقطة حفظ أو مستودع محدد، سجل الاختبارات الناجحة، قائمة المزايا التي تعمل في الإنتاج لا في المعاينة فقط، وقائمة **أسماء** متغيرات البيئة المطلوبة. تمر القيم نفسها عبر الأسرار المحمية للمشروع ولا تُنسخ إلى ملف أو رسالة.

## أولويات معروفة للمراجعة

تبدأ المراجعة بقوالب غرفة العمليات وحالات الواجهة الصادقة ومراقب الصحة، ثم قالب إنتاج الحلقة وبيانات SEO وسجل الحلقات بعد توثيق المصدر. لا تنتقل سكربتات النشر المباشر أو قراءة الأسرار من ملفات محلية أو cron ذي صيغة غير متوافقة كما هي؛ تعاد صياغتها ضمن حواجز ومهام المشروع الأساسي.

تملك النسخة الأساسية فحص تشغيل عام (`system.health`) فقط. لذلك يعد مراقب صحة المنصات المرشح من النسخة الثانية **ميزة مراجعة مستقلة**: لا يعتمد إلا بعد إثبات مصدر كل حالة، وتحديد التكرار، ومنع أي فحص من بدء نشر أو تجديد غير مدعوم.

ويجب أن يحافظ الدمج على حواجز مركز القنوات المثبتة حاليًا: تستمد وجهات النشر من الجاهزية الخادمية لا من جلسة متصفح، وتهيئة تطبيق Meta لا تساوي صلاحية رمز صفحة Facebook، ولا يظهر الغلاف كأنه طُبق خارجيًا لمجرد وجود رابط الأصل.

## معايير القبول

لا تعتمد ميزة من النسخة الثانية إلا إذا اجتازت: مراجعة الكود، اختبارًا آليًا مناسبًا، تحقق واجهة عند الحاجة، وتوافقًا مع الحواجز الحالية. لا يعد قبول TikTok معلنًا أو ربط Google/Meta أو وجود متغير في بيئة أخرى دليلاً كافيًا على جاهزية النشر في المشروع الأساسي.
