# إشعارات التشغيل

تسجل XDAW NOVA كل محاولة إشعار في سجل `notification_events`، سواء تم التسليم إلى Telegram أو تعذر بسبب عدم وجود تفويض أو مشكلة اتصال. لا يوقف فشل Telegram إنشاء المادة أو تسجيل فشل الرفع، ولا يعيد النظام المحاولة تلقائيًا.

| الحدث | وقت الإنشاء | الغرض |
|---|---|---|
| `review_required` | إضافة مادة أو رفع ملف أو توليد مشهد | تنبيه بأن الحقوق والسلامة تحتاجان قرارًا بشريًا |
| `youtube_upload_failed` | فشل رفع YouTube بعد إنشاء سجل التشغيل | تنبيه بالتعثر من دون إعادة محاولة صامتة |
| `facebook_upload_failed` | فشل رفع Facebook بعد إنشاء سجل التشغيل | تنبيه بالتعثر من دون إعادة محاولة صامتة |
| `project_review_required` / `project_blocked` | انتقال مشروع إلى المراجعة أو الإيقاف | تنبيه بالحالة الجديدة للمشروع |
| `tiktok_sandbox_draft_failed` | فشل إنشاء مسودة TikTok التجريبية | تنبيه بالتعثر من دون مساس بإنتاج TikTok |
| `schedule_needs_review` / `scheduled_youtube_failed` | حاجز جدول أو فشل رفع مجدول | إيقاف الجدولة المحتاجة للمراجعة ومنع التكرار |

> الإشعار تشغيلي فقط؛ لا يرفع فيديو ولا يفعّل نشرًا ولا يغير حالات الحقوق أو السلامة.

تتحول الجدولة المحجوبة إلى `needs_approval` بدل بقائها نشطة، لذلك يرسل النظام إشعارًا واحدًا عند الحاجز ثم يتوقف إلى أن يراجعها المستخدم. عند فشل الرفع، يتضمن التنبيه سبب المزود الفني بصورة مختصرة بعد حجب قيم `access_token` و`refresh_token` و`client_secret` وترويسات Bearer الظاهرة. اختبرت هذه الحراسة دون تنفيذ رفع خارجي.

تغطي الاختبارات انتقال مشروع تشغيلـي إلى `review`، وحجز الجدولة، وفشل الرفع، كما تثبت أن تعذر Telegram نفسه يسجل محاولة فاشلة ولا يعطل العملية الأصلية.
