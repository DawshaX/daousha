## مراجعة النشر المجدول

تظهر معاينة `server/scheduledPublishing.ts` أن المصدر المرجعي يقيّد التنفيذ الدوري بـYouTube، ويتحقق من حالة الجدول والمادة المرتبطة والحارس قبل الرفع، ويسجل سبب التوقف ويرسل تنبيهًا تشغيليًا. هذه حواجز متوافقة مبدئيًا مع نسختنا وليست مرشحًا لنسخ كامل؛ يجب مقارنتها مع تنفيذ المشروع الأساسي واختباراتها قبل أي نقل.

تعذر فتح رابط `raw.githubusercontent.com` للمستودع الخاص من الجلسة الحالية (404)، لذلك تظل قراءة الملفات عبر صفحات GitHub المصرح بها فقط إلى أن يتوفر تصدير المصدر أو تكامل GitHub رسمي. لا يحاول المشروع تجاوز هذا القيد أو استخدام رموز جلسة المتصفح.

بعد استخدام رابط التنزيل الخام عبر نطاق GitHub المصرح به، أمكن قراءة `scheduledPublishing.ts` كاملًا. يحقق الملف في جدولة نشطة، ويقصر النشر الدوري على YouTube، ويمنع التكرار، ويشترط أصل فيديو مخزنًا ومتصلاً، وتفويض قناة، واجتياز حارس الحقوق/المعاينة/السقف، ثم يحول أي تعثر إلى سجل وتنبيه. هذه هي نفس الفكرة الأساسية الموجودة في XDAW NOVA الحالي؛ لا توجد ضرورة لنسخه قبل مقارنة الاختبارات والتفاصيل.

لم يوجد `server/platformHealth.ts` في فرع GitHub الحالي رغم ذكره في حزمة تسليم منفصلة. لذلك يعامل مراقب صحة المنصات كمرشح من مصدر آخر أو نسخة محلية غير مسلّمة، لا كملف متاح للنقل من GitHub الآن.

## حارس النشر واختباراته

يطبق `publishingGuards.ts` حارسًا محدد النتائج: مفتاح الإيقاف، الأصالة والحقوق والسلامة، إقرار المعاينة، السقف اليومي، الفاصل الأدنى، النسخة الخاصة، ثم وضع النشر المحكوم. ويغطي اختبار مرافق كل هذه الحالات. يتطابق هذا النطاق مع حارس النسخة الأساسية واختباراتها؛ لذا يكون القرار الافتراضي **إعادة استخدام ما لدينا** بدل إدخال نسخة مكررة، ولا ينظر في دمج سطري إلا عند ظهور اختلاف وظيفي موثق.

## مولد النصوص الثنائية اللغة

مقارنة `server/contentBrain.ts` مباشرة أظهرت تطابقًا وظيفيًا وسطرًا بسطر مع مولد النسخة الأساسية: اختيار نموذج متاح، JSON Schema صارم، نصان عربي وإنجليزي متوازيان، وملاحظات حقوق وسلامة صريحة. **قرار النقل: لا شيء**؛ فالملف موجود ومطابق بالفعل في المشروع الأساسي.

## بنية الواجهة المرجعية

لا يحتوي `client/src` في فرع GitHub الحالي على مجلد `pages` أو ملف `Home.tsx` مستقل؛ يتكون من `components` و`index.css` فقط. لذلك لا يمكن نقل واجهة غرفة عمليات من مسار مفترض. تقتصر المراجعة التالية على مكونات الواجهة الفعلية داخل `client/src/components`، ثم تقارن بتركيب `DashboardLayout` و`Workspace` في النسخة الأساسية.

بعد فتح مجلد المكونات، ظهر أن GitHub يضع `Home.tsx` و`Workspace.tsx` و`DashboardLayout.tsx` داخل `client/src/components`، إلى جانب مكونات الاستوديو والمراجعة والجدولة والتحليلات نفسها: `AnalyticsBridge` و`AssetVault` و`ChannelControlCenter` و`ProjectBriefStudio` و`ReviewPublishDesk` و`ScheduleDeck` و`ScriptForge` و`SourceRegistry` و`TrendRadar` و`VisualForge`. هذه خريطة متطابقة تقريبًا مع البنية المحلية؛ يبدأ التدقيق التفصيلي بملف `Workspace` واختباراته إن وجدت، لا بنقل المجلد كاملًا.
